# 兼容版本与接入步骤

本文是实现入口，不是已实现的插件接口或可运行安装教程。当前没有选定经验证的运行组合。

## 先核实三个边界

1. **宿主扩展接口**：核实选定 LangBot 版本的 Runner 或其他正式插件接口，采用对应版本示例。
2. **查询服务合同**：读取实际 PSR 的认证、请求、会话、答案、引用、错误与运行标识字段，不预设新协议。
3. **交付配置接口**：将应用、身份解析与后端配置保持可注入；公开示例使用合成值。

## 最小实现

从与所选 SDK 版本匹配的官方插件示例开始，增加一个调用 PSR 的执行组件。按实际合同完成问题和可信身份传递、会话关联、结果与错误转换。LangBot 和 PSR 已提供的能力直接复用。

先让一条真实查询完成。额外工具选择、长期工作流、通用管理平台与其他后端由具体新增任务触发。

## 在首次可运行提交中记录

| 项目 | 应记录的信息 |
| --- | --- |
| LangBot Core 与 Plugin Runtime | 验证过的版本组合及来源 |
| 插件 SDK | 实际依赖版本与依赖锁 |
| 插件 | 版本、构建提交、可安装包及校验值 |
| PSR 合同 | 所支持的接口版本/行为，以及公开的合成输入输出 |
| 验证范围 | 已验证的行为、失败样例与仍未覆盖的能力 |

由交付环境记录真实应用绑定、后端部署版本与运行证据。插件发布和部署配置可以独立演进；新能力需要时再验证对应组合。

## 有意义的验证

- 本地或组件验证：用合成请求核对身份上下文传递、答案/引用/错误转换及相关会话行为。
- 集成验收：在授权环境中由 Lark 发起真实查询，核对后端实际回执与正确会话回送。
- 公共产物只附可公开的验证摘要，原始业务证据留在交付环境。
